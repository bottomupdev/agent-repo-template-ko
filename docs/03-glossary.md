# 용어

*같은 것을 여러 이름으로 부르면 에이전트는 다른 것으로 알고 따로 구현합니다. 코드, UI 문구, 문서에서 쓸 이름을
하나로 정하고, 쓰지 않을 동의어도 적어 둡니다.*

## 용어

*표 하나로 시작합니다. 코드 이름과 화면 이름이 다르면 둘 다 적습니다.*

| 용어 | 뜻 | 코드 이름 | 쓰지 않는 말 |
|---|---|---|---|

## 번호 체계

이 저장소에는 번호가 여러 종류 있습니다. 섞이지 않게 항상 종류를 함께 적습니다.

| 쓰는 모양 | 가리키는 것 | 있는 곳 |
|---|---|---|
| `D12` | 결정 | [01-decision-log.md](01-decision-log.md) |
| `할 일 질문 3` (`<영역> 질문 <번호>`) | 열린 질문(풀렸으면 묘비) | [02-open-questions.md](02-open-questions.md) |
| `ADR 0001` | 아키텍처 결정 기록 | [adr/](adr/README.md) |
| `issue #<번호>`, `PR #<번호>`, `<owner>/<repo>#<번호>` | GitHub 이슈·PR | GitHub |
| `항목 3`, `3단계` | 한 문서 안의 목록·절차 번호 | 그 문서 |

- `#숫자`는 GitHub 이슈·PR에만 씁니다. GitHub는 이슈 본문·PR 설명·커밋 메시지의 `#숫자`를 이 저장소의 이슈나
  PR 링크로 바꿉니다. 결정이나 질문에 붙이면 엉뚱한 이슈로 이어집니다.
- 번호는 다시 쓰지 않습니다. 풀린 질문과 대체된 결정도 번호를 지킵니다.

---

**예시 (가상의 할 일 앱)**

> | 용어 | 뜻 | 코드 이름 | 쓰지 않는 말 |
> |---|---|---|---|
> | 할 일 | 사용자가 적은 한 줄 작업. 제목, 마감일, 상태를 가짐 | `Task` | 투두, 아이템, 카드 |
> | 완료 | 할 일을 끝냈다고 표시한 상태. 목록 아래로 내려감 | `status: "done"` | 체크, 종료 |
> | 휴지통 | 삭제한 할 일이 7일 동안 머무는 곳(D2) | `trash` | 쓰레기통, 아카이브 |
> | 마감일 | 시간 없이 날짜만 가짐. 사용자 기기의 시간대로 해석 | `dueDate` | 기한, 데드라인 |
>
> "아카이브"는 쓰지 않습니다. 일부러 오래 남겨 두는 곳처럼 들려서, 7일 뒤 지워진다는 사실과 어긋납니다.
