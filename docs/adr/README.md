# ADR (아키텍처 결정 기록)

ADR(Architecture Decision Record)은 오래 남는 결정의 맥락, 고른 것, 버린 대안, 결과를 한 문서에 적습니다.
모든 결정은 먼저 [결정 기록](../01-decision-log.md)에 들어갑니다. ADR은 그중 일부에만 더합니다.

## 결정 기록 한 줄로 충분할 때와 ADR이 필요할 때

| 결정 기록만 | ADR도 |
|---|---|
| 이유가 한두 문장으로 설명됨 | 대안이 여럿이었고, 왜 버렸는지가 나중에 중요함 |
| 되돌리기 쉬움 | 저장 형식, 경계, 보안 모델처럼 되돌리기 비쌈 |
| 한 영역에만 영향 | 여러 구성 요소나 앞으로의 많은 PR에 영향 |

ADR을 쓰면 결정 기록 항목에 한 줄 요약과 ADR 링크를 두고, ADR에는 결정 번호를 적습니다.

## 파일 이름과 형식

- 파일 이름: `NNNN-짧은-제목.md` (예: `0002-trash-retention.md`). 번호는 네 자리로 하나씩 늘립니다.
- 첫 줄은 다른 문서처럼 `<!-- Summary: 한 줄 요약 -->`입니다.
- 머리 목록: `상태`, `날짜`, `결정`(결정 기록 번호), 해당하면 `고침`과 `대체`.
- 본문 절: `맥락`, `결정`, `결과`, `버린 대안`. 짧을수록 좋습니다. [0001-example.md](0001-example.md)를 봅니다.

## 상태

| 상태 | 뜻 |
|---|---|
| `Proposed` | 제안. 권위가 없습니다. 이 ADR만 보고 구현하지 않습니다 |
| `Accepted` | 받아들여짐. 지금 유효합니다 |
| `Amended` | 받아들여진 뒤 일부가 바뀜. 바뀐 내용은 `고침` 줄과 본문 끝 "고친 기록"에 있습니다 |
| `Superseded` | 다른 ADR로 대체됨. 기록으로만 남습니다 |

## 고칠 때는 기록합니다

- 받아들여진 ADR의 본문을 덮어쓰지 않습니다. 바뀐 부분은 머리의 `고침: <날짜>, D<n>` 줄과 본문 끝 "고친 기록" 절에
  더하고, 상태를 `Amended`로 바꿉니다.
- 결정이 통째로 바뀌면 새 ADR을 쓰고, 옛 ADR의 상태를 `Superseded`로 바꾸고 `대체: ADR <새 번호>`를 적습니다.
- 오타와 깨진 링크는 그냥 고쳐도 됩니다. 뜻이 바뀌는 수정만 기록합니다.

왜: 무엇이 언제 왜 바뀌었는지가 보여야, 옛 문장을 근거로 옛 방식을 되살리는 일이 없습니다.
