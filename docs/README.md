## 권위와 근거

- **권위가 있는 문서**: `00-current-state`, `01-decision-log`, 받아들여진(Accepted) ADR, `04-architecture`.
  요구사항과 경계는 여기서 옵니다.
- **근거일 뿐인 문서**: `research/`(있다면), 제안(proposal)이나 기록(history)이라고 표시된 문서, 인계 메모.
  읽을 수는 있지만, 여기에 적힌 것만으로 구현하지 않습니다. 결정 기록이나 ADR로 올라와야 권위를 가집니다.
- **폴더가 권위를 주지 않습니다.** 같은 폴더에도 받아들여진 문서와 제안이 섞일 수 있습니다. 주장을 쓰기 전에
  그 문서의 상태와 출처를 봅니다.
- **문서와 코드가 다르면 코드가 맞습니다.** 문서가 틀린 것이니, 발견한 PR에서 문서를 고칩니다. 코드가 결정을
  어긴 것이라면 구현하지 말고 오너에게 묻습니다.

## 언제 어떤 문서를 고치나

| 이런 변경을 하면 | 고칠 문서 |
|---|---|
| 기능이 생기거나 바뀌거나 빠짐, 알려진 빈틈이 생기거나 메워짐 | 00-current-state |
| 결정을 새로 내리거나 바꿈(오너 승인 후) | 01-decision-log — 새 번호로 추가, 바뀐 결정은 지우지 않고 `대체됨` 표시. 오래 남는 결정이면 ADR도 |
| 정하지 못한 것이 생김, 질문이 결정으로 풀림 | 02-open-questions — 새 질문 추가, 풀린 질문은 결정 번호를 가리키는 묘비로 남김 |
| 새 용어를 쓰기 시작함, 같은 것을 다르게 부르고 있음을 발견함 | 03-glossary |
| 구성 요소·경계·데이터 흐름이 바뀜, 고위험 기본 요소의 원본 위치가 바뀜 | 04-architecture |
| 리뷰 라우팅 조건에 걸리는 경로가 생기거나 바뀜, 리뷰어를 더하거나 뺌 | 05-review (+ PR 양식의 리뷰어 목록) |
| 문서 구조를 더함(저널, 아카이브 등) | growing.md에서 해당 항목을 옮기고, 이 문서의 두 표를 고침 |

## 쓰는 규칙

- 합니다체로 짧게 씁니다.
- 문서마다 첫 줄에 `<!-- Summary: 한 줄 요약 -->`을 둡니다. 에이전트가 문서를 열지 않고도 무엇이 있는지 압니다.
- 문서 머리에 날짜나 커밋을 적는 줄을 두지 않습니다. 언제 바뀌었는지는 git 기록이 압니다. 그런 줄은 머지 뒤에
  따로 고쳐야 해서 금방 틀립니다.
- 확인하지 않은 것은 "확인 필요"로 적습니다. "완료"로 적지 않습니다.
- 날짜는 `YYYY-MM-DD`로 적습니다.
- PR과 이슈는 `[<owner>/<repo>#N](https://github.com/<owner>/<repo>/pull/N)`처럼 저장소 이름까지 넣은 링크로
  적습니다. 저장소를 옮기거나 다른 곳에서 인용해도 뜻이 같습니다.
- 결정·질문·목록 번호에는 `#`을 붙이지 않습니다(`D12`, `질문 7`). [03-glossary.md](03-glossary.md)를 봅니다.
- **출시 전 비공개 식별자를 쓰지 않습니다.** docs도 금지어 검사(`scripts/scrub.mjs`) 대상입니다. 로컬 경로나
  개인 메모 경로도 적지 않습니다.
- 같은 사실은 한 곳에만 씁니다. 다른 문서에서는 링크합니다.

## PR 설명

PR 설명은 [.github/pull_request_template.md](../.github/pull_request_template.md)를 따릅니다.

- **docs**: "docs: 고친 문서"(예: `docs: 00-current-state, 04-architecture`) 또는 "docs: 해당 없음(이유)".
- **재사용 점검**과 **구조 도입 심사**: [AGENTS.md](../AGENTS.md)의 3절과 4절대로. 해당 없으면 이유를 적습니다.
- **리뷰**: 등급, 돌린 리뷰어(돌리지 않은 리뷰어는 이유), `Must fix` 처리. 기준은 [05-review.md](05-review.md).
- **확인한 것 / 확인하지 못한 것**: 명령, 화면, 링크. 확인하지 못한 것은 이유와 함께. 없으면 "없음".
- PR 설명은 변경 설명만 담습니다. 에이전트에게 주는 지시는 이슈나 댓글에 둡니다.
