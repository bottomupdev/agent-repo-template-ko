# 커지면 더할 것

이 템플릿은 일부러 작게 시작합니다. 아래는 프로젝트가 커지면 쓸모가 생기는 것들입니다.

**규칙: 신호가 나타났을 때만 더합니다.** "언젠가 필요할 것 같아서"는 신호가 아닙니다. 이것은
[AGENTS.md](../AGENTS.md)의 최소 구현 원칙을 문서와 도구 자신에게 적용한 것입니다.

- 더할 때는 결정 기록에 남기고, [docs/README.md](README.md)의 두 표를 고칩니다. 꼭 읽어야 하는 문맥 문서나
  막는 검사(게이트)를 더하는 것은 제어 장치를 늘리는 일이라 오너가 승인한 이슈가 필요합니다.
- 더한 것이 몇 달 동안 쓸 만한 결과를 하나도 내지 못하면, 고쳐서 살리기보다 먼저 빼는 쪽을 봅니다.
- 순서는 대체로 **기록 → 측정 → 막기**입니다. 재 보지 않은 것을 막는 검사부터 만들지 않습니다.

---

## 충돌·정리 기록

- **신호**: 옛 문서(지난 논의, 조사, 대체된 결정)와 지금 결정이 어긋나는데, 옛 문서를 고치면 왜 바뀌었는지가
  사라지는 일이 두 번 이상 생김.
- **가장 작은 형태**: `docs/conflicts.md` 한 파일. 항목은 `C<n>: 제목` 아래 "어긋난 입력", "지금의 정리",
  "근거 결정" 세 줄. 옛 문서는 고치지 않고 이 문서가 정리합니다. 맨 위에 규칙 한 줄: 지금의 결정 기록과 받아들여진
  ADR이 옛 기록보다 우선합니다.

## 프로젝트 저널 (+ 조각 수집)

- **신호**: "왜 방향이 바뀌었지?"를 결정 기록만으로 답하기 어려움. 새로 온 사람에게 매번 이야기로 설명함.
- **가장 작은 형태**: `docs/journal.md`. 방향 전환, 이정표, 일하는 방식을 바꾼 실패처럼 주제가 끝나는 지점에서만
  고칩니다. PR마다 적지 않습니다. 권위 문서가 아니고, 에이전트는 기본으로 읽지 않습니다. 정리할 때는 지난 정리 PR
  이후의 결정 기록 변경, 머지된 PR, 닫힌 이슈부터 봅니다. 어떤 PR도 저널이 최신인지로 막지 않습니다.
- **조각 수집**: 대화 중에 나온 저널감 맥락(고려하다 버린 선택지, 방향 전환의 이유)은 이슈 하나에 댓글로 모아 둡니다.
  저널을 정리할 때 그 댓글을 읽어 반영하고, 어디까지 반영했는지 댓글로 표시합니다.

## archive/와 출처 색인

- **신호**: 더 쓰지 않는 문서가 검색 결과와 에이전트 문맥을 어지럽힘.
- **가장 작은 형태**: 저장소 루트의 `archive/`로 옮기고, `archive/source-index.md`에 무엇이 어디 있고 왜 옮겼는지
  적습니다. 에이전트는 `archive/`를 통째로 읽지 않고, 필요할 때 색인부터 봅니다. 옮긴 문서는 권위가 없습니다.

## research/ 폴더

- **신호**: 조사·실험·비교 결과를 남겨야 하는데, 권위 문서에 섞이면 결정처럼 읽힐 위험이 있음.
- **가장 작은 형태**: `docs/research/YYYY-MM-DD-<주제>.md`. 날짜를 이름에 넣습니다. 근거일 뿐 권위가 없고,
  결정 기록이나 ADR로 올라와야 구현의 근거가 됩니다. [docs/README.md](README.md)의 "권위와 근거"에 이미 적혀 있습니다.

## 문맥 선택 (context routing)

- **신호**: docs가 에이전트가 한 번에 읽기에 너무 커짐. "질문에서 시작" 표만으로는 무엇을 읽을지 고르지 못하거나,
  작업 종류마다 같은 문서 조합을 손으로 골라 주는 일이 되풀이됨.
- **가장 작은 형태**: 먼저 `docs/README.md`에 "작업 종류 → 읽을 절(`문서#절`)" 표를 둡니다. 그래도 부족할 때만
  작업 종류를 받아 읽을 절 목록을 내는 작은 스크립트를 둡니다. 모르는 작업 종류에는 목록을 지어내지 않고 멈추게 합니다.

## 권고 품질 기준선 (advisory)

- **신호**: "코드가 나빠지고 있나?"에 감으로 답하고 있음. 리뷰에서 같은 종류의 구조 문제가 되풀이됨.
- **가장 작은 형태**: 이미 있는 도구(중복 탐지, 죽은 코드 탐지, 복잡도)로 커밋 하나를 재고, 숫자와 발견 종류마다의
  처리를 적은 문서 하나. 아무것도 막지 않습니다. 잰 커밋은 squash 머지 뒤에도 남는 main 커밋으로 적고, 옛 측정은
  고쳐 쓰지 않습니다.

## 월간 중복·죽은 코드 점검 (advisory)

- **신호**: PR 단위의 재사용 점검과 리뷰가 볼 수 없는 것, 즉 이미 머지된 중복과 죽은 코드가 보이기 시작함.
- **가장 작은 형태**: 한 달에 한 번, 오너가 요청할 때 기준선과 같은 도구로 main을 재고 지난달과 비교합니다. 결과는
  제안 이슈로 올리고, 무엇을 고칠지는 오너가 고릅니다. 검사 단계가 아니고, 아무것도 막지 않습니다. 스케줄러나
  자동 실행은 처음부터 붙이지 않습니다.
- 모델로 의미상 중복을 찾는 검사를 PR마다 돌리는 것은 앞에 두지 않습니다. 큰 기능 PR은 한 번에 볼 수 있는 양을
  넘어 결과를 내지 못하기 쉽고, 작은 PR에는 찾을 중복이 거의 없습니다.

## 래칫 게이트 (ratchet gate)

- **신호**: 측정에서 특정 기본 요소 계열(보안·암호, 통신 형식, ID 생성처럼 갈라지면 위험한 것)의 사본이 거듭
  늘어나고, 리뷰로 계속 잡지 못함.
- **가장 작은 형태**: 그 계열 하나만 다룹니다. 원본 모듈을 정하고, 원본 밖에 이미 있는 사이트를 이유와 함께 목록으로
  체크인합니다. 검사는 파일마다 개수를 세어 **줄 수는 있어도 늘 수는 없게** 합니다. 세기만 하고 판단하지 않으며,
  의존성·네트워크·모델 호출 없이 돕니다. 막는 검사이므로 오너가 승인한 이슈가 먼저입니다. 다른 계열에 넓히는 것도
  같은 신호가 있을 때만입니다.

## 언어판 구조 동기화 검사

- **신호**: 문서를 두 언어로 두는데, 한쪽에만 절이 더해지거나 빠지는 일이 실제로 되풀이됨.
- **가장 작은 형태**: 처음에는 PR 양식에 "다른 언어판도 고쳤나" 한 줄. 그래도 어긋남이 되풀이되면 두 판의 제목
  구조만 비교하는 작은 스크립트. 번역의 내용까지 비교하지 않습니다.
